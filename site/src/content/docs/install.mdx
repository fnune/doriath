## Get doriath

<Tabs syncKey="install">
  <TabItem label="Release binary">
    The binary is static and has bubblewrap inside. Download it for `amd64` or `arm64`, check it and put it on your `PATH`:

    ```sh
    base=https://github.com/fnune/doriath/releases/latest/download
    curl -fLO "$base/doriath-linux-amd64" -fLO "$base/doriath-linux-amd64.sha256"
    sha256sum -c doriath-linux-amd64.sha256
    install -m 755 doriath-linux-amd64 ~/.local/bin/doriath
    ```

  </TabItem>
  <TabItem label="home-manager">
    Add the flake as an input, import its module and enable it. The [home-manager guide](/guides/home-manager/) lists the options.

    ```nix title="flake.nix"
    inputs.doriath = {
      url = "github:fnune/doriath";
      inputs.nixpkgs.follows = "nixpkgs";
      inputs.home-manager.follows = "home-manager";
    };
    ```

    ```nix title="home.nix"
    {
      imports = [ inputs.doriath.homeManagerModules.default ];
      programs.doriath.enable = true;
    }
    ```

  </TabItem>
  <TabItem label="NixOS">
    doriath needs no system service. Add the package:

    ```nix title="flake.nix"
    inputs.doriath = {
      url = "github:fnune/doriath";
      inputs.nixpkgs.follows = "nixpkgs";
    };
    ```

    ```nix title="configuration.nix"
    environment.systemPackages = [ inputs.doriath.packages.${pkgs.system}.default ];
    ```

  </TabItem>
  <TabItem label="Go">
    This build has no bubblewrap inside. It uses the `bwrap` on your `PATH`, or the one that `DORIATH_BWRAP` names.

    ```sh
    go install github.com/fnune/doriath/cmd/doriath@latest
    ```

  </TabItem>
  <TabItem label="From source">
    The dev shell has Go and the static bubblewrap that `just build` embeds.

    ```sh
    git clone https://github.com/fnune/doriath
    cd doriath
    nix develop --command just build
    ```

  </TabItem>
</Tabs>

Then check the machine:

```sh
doriath doctor
```

Without an installation, `nix run github:fnune/doriath -- doctor` does the same check.

doriath needs Linux with unprivileged user namespaces. macOS is out of scope for now. The [`podman` module](/reference/modules/#podman) also needs podman, util-linux `unshare` and `nsenter`, and subordinate ids for your user. `grep $USER /etc/subuid /etc/subgid` shows these ids.

## Write a profile

A profile is a TOML file that describes one kind of work. It lists [modules](/reference/modules/), and each module holds the hosts, caches and rules of one tool. This profile builds with Go and Node, commits with git, reads documentation sites and runs Claude Code:

```toml title="~/.config/doriath/profiles/my-app.toml"
description = "My app"
modules = ["base", "vcs", "docs", "go", "node", "claude"]
```

For another agent, use its module instead of `claude`, as [agents](/agents/) describes. `doriath profiles show my-app` shows what the profile allows, and which module allows each part.

The repository is read-only in the jail, and the agent commits in worktrees. The `claude` module puts them in `.claude/worktrees`. To use another folder, add it as a mount:

```toml
[[mounts]]
path = "~/Development/.worktrees/my-app"
mode = "write"
```

## Create credentials for the profile

Make new credentials for each profile. Then a token can reach only the repositories of its profile, and you can revoke it alone. The agent never reads the credentials, because doriath adds them outside the jail.

These steps are for GitHub. [Forges](/forges/) has the steps for GitLab, Forgejo and Bitbucket.

1. Create a [fine-grained token](https://github.com/settings/personal-access-tokens/new) for the repositories of this profile. Give it an expiry, and read and write access to Contents, Pull requests, Actions and Commit statuses.
2. Keep the token in your password manager under a name such as `github-my-app`.
3. Create an SSH key for commit signing, and add it to GitHub as a signing key. The commits of the agent then show as verified, with you as the author.

```sh
install -d -m 700 ~/.config/doriath/keys
ssh-keygen -t ed25519 -N '' -C 'doriath my-app signing' -f ~/.config/doriath/keys/my-app-signing
cat ~/.config/doriath/keys/my-app-signing.pub
```

Then add the `github` module, so that the agent can push and open pull requests. Each `[secrets.NAME]` table gives the source of one secret: a file with mode 600, or a command that prints it.

```toml title="~/.config/doriath/profiles/my-app.toml"
description = "My app"
modules = ["base", "vcs", "docs", "go", "node", "github", "claude"]

[secrets.github]
command = ["rbw", "get", "github-my-app"]

[secrets.signing]
file = "~/.config/doriath/keys/my-app-signing"

[signing]
key = "signing"
```

The `github` module asks for the secret `github`, so that name is fixed. You choose the name of the signing secret, and `[signing] key` must use it. [Secrets](/reference/configuration/#secrets) has the details.

## Find the hosts of a build

A first build usually needs hosts that the modules do not name. In learning mode, every public host is reachable for one session. At the end, doriath prints the `[egress]` lines to add to the profile:

```sh
doriath run --profile my-app --learn -- make build
```

<Aside type="caution">
  Learning mode reaches every public host. Use it only for builds that you start
  yourself, and never give it to an agent.
</Aside>

## Run an agent

Start the agent from the repository. For another agent, use its command instead of `claude`.

```sh
cd ~/Development/my-app
doriath run --profile my-app -- claude
```

Held requests show as desktop notifications. Without a desktop, use `doriath web open` or `doriath approvals`, as [answering requests](/guides/approvals/) describes.

A plain `claude` still runs outside the jail. To start it in the jail, use an alias such as `alias claude-app='doriath run --profile my-app -- claude'`. For a whole project, use a line in its `.envrc`, as [projects with direnv](/guides/direnv/) describes.
