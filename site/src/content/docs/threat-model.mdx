## Assumptions

doriath assumes an agent that acts against your intent, because of a prompt injection or a mistake. The agent runs any program that the jail sees, writes any file that it can write, and tries all that the kernel allows. [Architecture](/architecture/) describes the parts behind each guard.

## Guarded actions

| Attempt                                              | Guard                                                                                                                                                            |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Read your home directory, SSH keys or other projects | The jail does not mount them. It sees the repository, the profile's paths and system paths.                                                                      |
| Read a token, or send it to another host             | Tokens stay in the proxy, which adds them only for the programs and hosts that the profile names.                                                                |
| Reach a host that the profile does not name          | The jail has only loopback. The proxy holds unknown hosts for your approval.                                                                                     |
| Reach your local network or a cloud metadata service | The proxy refuses private, link-local and metadata addresses, whatever name resolves to them.                                                                    |
| Merge, release or push without you                   | `[[http]]` rules hold those requests until you [answer](/guides/approvals/).                                                                                     |
| Approve its own requests                             | Answers come from your desktop, terminal or approvals page, which the jail cannot reach.                                                                         |
| Change your checkout, or plant a git hook            | The checkout is read-only. git's and jj's config, hooks and info stay read-only, also in writable mounts.                                                        |
| Rewrite or delete history                            | Existing packs are read-only. At the end, doriath restores loose objects and removes objects that git cannot verify. `doriath restore` resets moved branches.    |
| Escape through the kernel                            | seccomp refuses namespaces, mounts, `ptrace`, `bpf`, `io_uring`, kernel modules, keyrings, terminal injection and rare socket families. Landlock limits writes.  |
| Reach more through containers                        | A broker checks each podman API call. It permits only allowed images and the profile's mounts, nothing privileged, and no host namespace other than the network. |

## Limits

<Aside type="caution">
  Do not put work that an agent must not see in its profile. An allowed host can
  receive all that the agent reads.
</Aside>

No limit below lets an agent leave the jail, take a credential or reach a host that the profile does not name. To make the limits smaller, mount only the project, allow only the hosts that the task needs, and do not put secrets in world-readable paths.

### Allowed hosts

Each allowed host can receive data, because work needs writes. The shipped modules allow dozens of hosts.

- The agent can send its own API key to api.anthropic.com. The `claude` module refuses requests that carry `x-api-key`.
- The `github` module lets `gh` post comments. doriath cannot hold comments outside your repositories, because GraphQL names the repository by an opaque ID.
- For a host without an `[[http]]` entry, doriath checks only the host and the TLS server name. Behind a CDN, the request can name any site on that CDN, and Encrypted Client Hello can hide the server name.

Interception of every host would break gRPC clients such as Bazel's remote cache, because the interceptor speaks only HTTP/1.1.

### Allowed programs

Credentials and `[[egress.programs]]` hosts go only to named programs. This stops only stray programs. The agent can still:

- run a named program with any arguments, steer it through writable config such as `~/.config/gh`, or preload a library into it.
- give a TCP socket to a named program after another program writes the request, because doriath names the program when the connection opens.
- replace a program at a writable path, such as Playwright's browser in its cache. doriath warns about each such path, and a pin by hash for the session would stop this.

Request rules and approvals decide what named programs can do, because the agent needs them.

### System paths and kernel calls

The agent can read each world-readable file in `/etc`, `/nix/store`, `/usr`, `/sys` and other system paths, including secrets in the nix store. A read allowlist would break the host toolchain, which reads widely.

seccomp allows netlink beyond routing, nested seccomp filters and `memfd_create`, because Chromium, .NET and `ss` break without them. Code in memory gives the agent nothing new, because a file that it writes can also run.

### Shared kernel and user

The jail runs as your UID on the host kernel, so a kernel or bubblewrap bug lets the agent escape as your user. Only a virtual machine isolates more. In exchange, the agent's files belong to you, and a session starts in less than a second on your toolchain.

- The podman service runs as root in a subordinate user namespace, without its own seccomp filter. A container runtime escape gets that access, but the agent reaches only the broker.
- doriath does not check or pin the base images that a build pulls in podman.
- The agent can send signals to doriath's init, which is non-dumpable. A kill ends the session. A stop holds new proxy connections, so the agent chooses when doriath names the program behind each one.

### Writable repositories

With the `vcs` module, the agent creates, moves and deletes branches and adds worktrees. At the end, doriath repairs the store and its submodules as the guarded actions describe.

git on your machine follows the `.git` file and admin directory of an agent worktree, so `git status` there can run hooks that the agent wrote. doriath resets these files in milliseconds, again at the end or at the next `doriath run`, and reports each change. These cases stay open:

- doriath only reports a worktree that claims a path outside the writable mounts, or reaches outside them through a symlink.
- git on your machine follows the config and hooks of a `.git` directory that the agent creates elsewhere in a write mount, as with an `.envrc`.
- In a `write` mount of your checkout, `.envrc` and editor tasks are writable. Only git's and jj's control files stay read-only.

Review the files of an agent worktree as you review a pull request. Worktrees let agents work in parallel, and a copy for each session would cost disk, time and a step to land the work.

doriath holds each push for your approval, but it does not decide which branches a push can change. Rules such as the refusal of a force push to main belong in the forge's branch protection, which you set in the repository.

### Trust that returns to the host

- Claude's transcripts return to `~/.claude/projects`, so a session that you resume outside the jail reads history that the agent wrote.
- The agent reads the project's earlier transcripts, also text that you pasted into a session outside the jail.
- Escape sequences in agent output can change your terminal title or state.
- One session can plant files in caches and container storage that later sessions of the same profile trust.
- `doriath grant write` on the host can attach a directory that the jail does not see, and so lets the agent read it. A grant lasts until the session ends, because an open file stays open after doriath removes a mount.

These paths let you resume sessions, read output, reuse build caches and add writable paths without a restart. The helper that applies each grant has full capabilities over the mounts. It runs doriath's own read-only binary and never follows symlinks.

### Other trust

- `doriath run --learn` reaches every public host for that session. Use it only for builds that you start, and never give it to an agent.
- `doriath forward` listens on the host's loopback, which every local user can reach, also on a shared server.
- The `nix-daemon` module's builds run outside the jail, without the allowlist.
- A secret given as a command runs on the host with your environment, so it trusts the author of the profile.
- OAuth refresh tokens stay in doriath's state directory, which your user can read outside the jail, as with your other logins.
- Claude's Remote Control lets anyone signed in to the profile's claude.ai account drive the session and answer Claude's permission prompts. The jail and the proxy rules still apply.
- Tool requests carry text that the agent wrote, and the notification says so. A long run of requests invites a click on allow, so doriath refuses new requests while 32 wait. It shows other notifications 10 at once, then one a minute.
- Sessions have task and memory limits but no CPU quota by default. `[limits] cpu` sets one.

## Other sandboxes

This table compares doriath with other ways to isolate a coding agent. Each cell gives the control that the tool has for the threat in its default or documented setup. The facts come from the documentation and source of each project, read in October 2026.

doriath is not the strictest tool in this table. It shares your kernel, where a microVM puts a separate kernel between the agent and your machine, and its code is young and not audited. doriath makes it easy to choose how much each project can reach: hosts, paths, methods and tokens, with requests that wait for your answer. If a kernel exploit is the threat that matters most, run doriath in a VM, or use a microVM tool and accept its coarser rules.

### doriath

doriath runs the agent in a bubblewrap jail with user, mount, PID and network namespaces, seccomp, Landlock and only loopback. A proxy on the host enforces the profile's hosts and credentials and holds merges, releases and pushes for approval. The jail shares the host's kernel, toolchain and system paths.

### Claude Code sandbox

The sandbox covers Bash, PowerShell and Monitor commands. File tools, MCP servers and hooks run outside it, and the `srt` runtime can wrap the whole process. Reads cover "the entire computer, except certain denied directories". The proxy decides on the host name and does not inspect TLS by default, and the docs warn about domain fronting. Mask mode needs `tlsTerminate` and settings outside the repository. Claude can retry a command unsandboxed unless `allowUnsandboxedCommands` is false. Sources: [sandboxing](https://code.claude.com/docs/en/sandboxing), [sandbox-runtime](https://github.com/anthropics/sandbox-runtime), [sandbox environments](https://code.claude.com/docs/en/sandbox-environments).

### NVIDIA OpenShell

A supervisor outside the workload decides each connection, and the workload has no network of its own. Rules name the host, port and calling binary. L7 `enforcement` defaults to `audit`, which logs and forwards. Agents can propose rules, which a human approves, or automatic approval applies when the risk checks pass. The Docker, Podman and Kubernetes drivers share the host kernel. The MicroVM driver needs KVM and is not auto-detected. Bind mounts need `enable_bind_mounts` and "can bypass workspace isolation". Version 0.1.5, October 2026. Sources: [architecture](https://docs.nvidia.com/openshell/latest/about/architecture), [best practices](https://docs.nvidia.com/openshell/latest/security/best-practices), [runtimes](https://github.com/NVIDIA/OpenShell/blob/main/docs/how-it-works/sandboxes/runtimes.mdx), [advisor](https://github.com/NVIDIA/OpenShell/blob/main/docs/how-it-works/policies/advisor.mdx).

### Docker Sandboxes

This column is here because Docker Sandboxes is a widely available local microVM for agents, and Claude Code's docs name it. Each sandbox has its own Docker daemon. A host proxy carries all outbound TCP, and "raw credential values never enter the VM". The docs warn that git hooks "do not appear in git diff output". It is closed source. Sources: [architecture](https://docs.docker.com/ai/sandboxes/architecture/), [security](https://docs.docker.com/ai/sandboxes/security/).

### Hosted microVM

E2B runs each sandbox in a Firecracker microVM, with outbound access on by default. Its domain rules match only the HTTP Host and TLS SNI, and a proxy adds secret headers outside the sandbox. Claude Code cloud sessions run in an Anthropic VM, where a GitHub proxy holds the credential. The docs say that the Anthropic API stays reachable with network access off. Both run away from your machine, so the agent sees no local files. Sources: [internet access](https://docs.e2b.dev/sandbox/internet-access), [persistence](https://docs.e2b.dev/sandbox/persistence), [Vercel AI SDK](https://docs.e2b.dev/agents/vercel-ai-sdk), [Claude Code on the web](https://code.claude.com/docs/en/claude-code-on-the-web).

### Plain container

A devcontainer shares the host kernel and bind-mounts the project read-write. Claude Code's docs say that a container does "not prevent a malicious project from exfiltrating anything accessible inside the container, including the Claude Code credentials". The reference `init-firewall.sh` resolves allowed domains to IP addresses at start and allows the host's /24 network. Sources: [devcontainer](https://code.claude.com/docs/en/devcontainer), [init-firewall.sh](https://github.com/anthropics/claude-code/blob/main/.devcontainer/init-firewall.sh).

### Separate Unix user

A second account relies on Unix file permissions, with no namespaces, seccomp or proxy. Files of mode 700 in the user's home stay closed, and world-readable files and the shared /tmp stay open. Network limits need root, for example an nftables `meta skuid` rule to a proxy. Source: [nftables metainformation](https://wiki.nftables.org/wiki-nftables/index.php/Matching_packet_metainformation).

### nono

nono is an Apache-2.0 tool, version 0.80.0 from 13 October 2026, with commits in the week of writing. It uses Landlock and seccomp on Linux and Seatbelt on macOS. Network access is "unrestricted" until a domain rule applies, and plain allowed hosts go through tunnels with end-to-end TLS. A supervisor can prompt on the terminal for file access outside the grants. Sources: [repository](https://github.com/nolabs-ai/nono), [networking](https://github.com/nolabs-ai/nono/blob/main/docs/cli/features/networking.mdx), [credential injection](https://github.com/nolabs-ai/nono/blob/main/docs/cli/features/credential-injection.mdx), [supervisor](https://github.com/nolabs-ai/nono/blob/main/docs/cli/features/supervisor.mdx).

### Facts not confirmed

- Docker Sandboxes: refusal of private or metadata addresses, and any approval step for single requests.
- E2B: refusal of private or metadata addresses by default.
- OpenShell: whether middleware can hold one request for a human.
- nono: guards against writes to `.git/hooks` or `.git/config`, and whether the agent can reach the supervisor's terminal prompt.
- Claude Code cloud sessions: which git operations the GitHub proxy limits.
