title: Claude Code
description: What doriath sets up for Claude Code, and the choices left to you.

Your Claude configuration needs no change. The [`claude` module](/reference/modules/#claude) gives each profile its own `~/.claude`, with your `CLAUDE.md`, settings and skills as read-only files. Each session starts with a fresh copy of your plugins, which Claude can write to, and nothing it writes there reaches yours. The login stays on the host: doriath holds it, and the proxy adds it to requests, so Claude never reads a token. A new profile starts with your onboarding done. [The login](#the-login) shows how to sign in.

## The login

Run this command on the host, one time:

```sh
doriath profiles login my-app
```

doriath opens the Claude sign-in page in your browser, and keeps the login in the [keyring](/reference/configuration/#oauth-logins) of your desktop. Every profile with the `claude` module shares this one login, so you sign in once. The entry has the service `doriath-oauth` and the account `module:claude/claude`. You can name any profile that has the module.

- A session without the login stops before Claude starts, and prints the command to run.
- Claude gets the placeholder `doriath-placeholder` in `CLAUDE_CODE_OAUTH_TOKEN`. The proxy replaces it with the real token on `api.anthropic.com` and `claude.ai`, for the `claude` program only.
- The jail cannot open the sign-in pages, so Claude cannot sign in by itself.
- Claude Code keeps its own login in `.credentials.json` in its config directory. The `claude` module deletes that file in the cache of the profile at each session start, because it would hold a refresh token that the agent can read. `doriath doctor` reports such files.
- To use another source for one profile, such as an API key from a password manager, give `[secrets.claude]` in the profile. It replaces the login of the module.

Claude sends the token only to `api.anthropic.com` and `claude.ai`. Two features can still fail: connectors, which reach `mcp-proxy.anthropic.com` and stay off, and Claude in Chrome, whose `bridge.claudeusercontent.com` connection the proxy does not touch, so it has no token.

## The adapter

doriath starts Claude with settings that it generates:

- claude.ai connectors are off.
- The `ask` and `deny` rules of the profile apply.
- The `.claude/settings.json` of the repository stays as it was at session start, so the agent cannot loosen its own permissions.
- At session start, Claude learns what the jail allows, what `doriath:` errors mean, and how to ask for a host or a writable path.
- Permission prompts go to the [approval queue](/guides/approvals/). If you do not answer in time, Claude shows its own prompt. A question that Claude asks you, such as a choice between options or a plan to approve, stays in Claude.
- Claude's notifications reach your desktop through doriath.
- MCP servers come from the [`[[mcp]]`](/reference/configuration/#mcp-servers) list of the profile. Your own MCP servers stay outside the jail.
- When the session ends, doriath copies the transcripts back to your `~/.claude`, so you can resume outside the jail.

Set the adapter under `[claude]` in the profile. `tool_wait` in [`config.toml`](/reference/configuration/#configtoml-keys) sets how long a permission prompt waits for you before Claude shows its own.

```toml
[claude]
disable_connectors = true
ask = ["mcp__claude-in-chrome__javascript_tool"]
deny = []
```

## Connectors

The `claude` module turns claude.ai connectors off, because a connector reaches your accounts through Anthropic, where doriath cannot see the calls. To use some connectors, turn them on and list them in `allowed_mcp_servers`, by the connector's URL or by its name. Claude then refuses all other connectors and MCP servers, except the `[[mcp]]` servers of the profile, which doriath adds to the list.

```toml
[claude]
disable_connectors = false
allowed_mcp_servers = ["https://mcp.example.com/mcp"]

[egress]
allow = ["mcp-proxy.anthropic.com"]
```

Claude reaches the connectors through `mcp-proxy.anthropic.com`, which the `claude` module refuses while connectors are off. To find the name and URL of each connector, run `/mcp` in a session outside doriath.

## Claude in Chrome

Claude in Chrome works in the jail with no change to the profile. Chrome starts a native host outside the jail, which puts a socket in `/tmp/claude-mcp-browser-bridge-<user>`. The `claude` module shows that directory read-only, and allows `bridge.claudeusercontent.com`, which Claude also uses to reach the extension. Open Chrome before the session starts, because doriath skips the directory if it does not exist yet. A profile that existed before you turned on Claude in Chrome does not have the setting, so run `/chrome` once in a session, or start Claude with `--chrome`.

The browser runs outside the jail, with your sign-ins, and its requests do not go through the proxy. The `claude` module makes `javascript_tool` and `file_upload` ask first. The other Chrome tools, such as navigation and clicks, do not ask. To make them ask, add them to `ask`, or turn Chrome off with `/chrome` in the session.

## Remote Control

To continue a session from claude.ai or the Claude app, start `claude --remote-control` or run `/remote-control`. Remote Control uses the claude.ai login of the profile. Remote Control needs Claude's feature flags, which the `claude` module keeps, as [Telemetry](#telemetry) explains.

Permission prompts go to the doriath queue first, and to your phone if you do not answer in time. A command that you allow from the phone still goes through the proxy and its rules. Anyone with the claude.ai login of the profile can control the session, within the same jail.

## Telemetry

The `claude` module refuses the usage events of Claude Code at the proxy. It does not set `DISABLE_TELEMETRY`, because that variable also stops the fetch of Claude's feature flags, which Remote Control needs.

- The proxy refuses `POST /api/event_logging/**` on api.anthropic.com.
- Egress refuses `*.datadoghq.com`, so you get no prompt for it.
- The flags come from `/api/eval` on api.anthropic.com. To fetch them, Claude sends Anthropic the attributes that choose your flags, such as your account and the Claude version.
- `DISABLE_ERROR_REPORTING`, `DISABLE_FEEDBACK_COMMAND` and `DISABLE_AUTOUPDATER` stay set.

## Sharing your login

To share your own login with the profile, mount the credentials file writable. The agent can then read the token, so do this only for a profile that you trust as much as yourself.

```toml
[[mounts]]
path = "~/.claude/.credentials.json"
mode = "write"
```
