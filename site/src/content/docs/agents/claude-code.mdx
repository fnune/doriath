Your Claude configuration needs no change. The [`claude` module](/reference/modules/#claude) gives each profile its own `~/.claude`, with your `CLAUDE.md`, settings, skills and plugins as read-only files. The login belongs to the profile, so run `/login` once in a session: doriath opens the sign-in page in your browser, and forwards the answer back into the jail. A new profile starts with your onboarding done.

## The adapter

doriath starts Claude with settings that it generates:

- claude.ai connectors are off.
- The `ask` and `deny` rules of the profile apply.
- The `.claude/settings.json` of the repository stays as it was at session start, so the agent cannot loosen its own permissions.
- At session start, Claude learns what the jail allows, what `doriath:` errors mean, and how to ask for a host or a writable path.
- Permission prompts go to the [approval queue](/guides/approvals/). If you do not answer in time, Claude shows its own prompt. A question that Claude asks you, such as a choice between options or a plan to approve, stays in Claude.
- Claude's notifications reach your desktop through doriath, except its notice that it waits for your next message, which Claude does not show on the desktop either.
- MCP servers come from the [`[[mcp]]`](/reference/configuration/#mcp-servers) list of the profile. Your own MCP servers stay outside the jail.
- When the session ends, doriath copies the transcripts back to your `~/.claude`, so you can resume outside the jail.

Set the adapter under `[claude]` in the profile, and what every adapter shares under `[agent]`:

```toml
[agent]
# How long a permission prompt waits for you before Claude shows its own.
approval_timeout = "60s"

[claude]
disable_connectors = true
ask = ["mcp__claude-in-chrome__javascript_tool"]
deny = []
```

## Connectors

The `claude` module turns claude.ai connectors off, because a connector reaches your accounts through Anthropic, where doriath cannot see the calls. To use some connectors, turn them on and list them in `allowed_mcp_servers`, by the connector's URL or by its name. Claude then refuses all other connectors and MCP servers, except the `[[mcp]]` servers of the profile, which doriath adds to the list.

```toml
[claude]
disable_connectors = false
allowed_mcp_servers = ["https://mcp.example.com/mcp"]

[egress]
allow = ["mcp-proxy.anthropic.com"]
```

Claude reaches the connectors through `mcp-proxy.anthropic.com`, which the `claude` module refuses without asking you while connectors are off.

`/mcp` in a session outside doriath shows the name and URL of each connector.

## Remote Control

To continue a session from claude.ai or the Claude app, start `claude --remote-control` or run `/remote-control`. Remote Control uses the claude.ai login of the profile. The `claude` module keeps the feature-flag fetch that Remote Control needs, and turns off telemetry, error reports, feedback and updates.

Permission prompts go to the doriath queue first, and to your phone only if you do not answer in time. After an answer from the phone, the command still goes through the proxy and its rules. Anyone with the claude.ai login of the profile can control the session. The jail rules stay the same for that person.

## Sharing your login

To share your own login with the profile, mount the credentials file writable. The agent can then read the token, so do this only for a profile that you trust as much as yourself.

```toml
[[mounts]]
path = "~/.claude/.credentials.json"
mode = "write"
```
