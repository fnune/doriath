title: GitLab
description: Use the gitlab module with a project access token for each profile.
---

The [`gitlab` module](/reference/modules/#gitlab) gives your token to `git` and `glab` on `gitlab.com`. `git` sends it with basic auth, and `glab` in the `PRIVATE-TOKEN` header.

## Token

Create a project access token or a group access token for the projects of the profile. Give it the Developer role, an expiry, and the scopes `api`, `read_repository` and `write_repository`. Then add it to the profile:

```toml
[secrets.gitlab]
command = ["rbw", "get", "gitlab-my-app"]
```

`glab` needs a token to start. The module gives it a placeholder in `GITLAB_TOKEN`, and the proxy replaces the `PRIVATE-TOKEN` header with your token on each request.

## Commit signing

GitLab verifies commits that are signed with an SSH key of the usage type Signing. Add the key of the profile, as [install](/install/#create-credentials-for-the-profile) shows.

## Requests

- Go through: reads, merge requests, issues, notes, and retries or cancels of pipelines and jobs.
- Wait for your answer: merges of merge requests, releases, tags, commits through the API, pushes, and the API requests that the module does not name, GraphQL included.
- Refused: changes to webhooks, CI variables, members, deploy keys, deploy tokens, access tokens and protected branches.

Branch rules, such as no force push to `main`, belong in the protected branches of the project.

The GitLab API names a project by its ID or by its path, such as `group%2Fsub%2Fproject`. The module lets the proxy read these paths, thus an allow for the session covers one project.
