`doriath run --profile NAME -- COMMAND` starts a proxy and an approval queue on the host, and runs the command in a jail. When the command exits, doriath repairs your repositories and prints one line on what it allowed, held and refused.

<Architecture />

## The jail

bubblewrap, inside the `doriath` binary, creates the namespaces of the jail. The agent runs as your user in them.

| Part    | Inside the jail                                                                                                                                                                          |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Files   | The system is read-only, and so is your repository unless the profile makes it writable. Home, `/run`, `/tmp` and `/var` start empty. Other paths appear only if the profile names them. |
| Kernel  | seccomp refuses namespaces, mounts, `ptrace`, `bpf`, `io_uring` and terminal injection. Landlock limits writes to home, `/tmp` and the writable mounts.                                  |
| Network | Loopback only. Every connection goes through the proxy.                                                                                                                                  |
| Limits  | A systemd user scope with task and memory limits, and a CPU quota if the profile sets one.                                                                                               |

The jail gets `PATH`, the terminal and locale variables, and the host variables that the profile passes. doriath drops all others.

## The proxy

The proxy runs on the host and checks each connection in this order:

1. The host must be in [`[egress] allow`](/reference/configuration/#profile-keys) of the profile or its modules. Another host becomes a request for you.
2. The address must be public. The proxy refuses private, link-local, shared and metadata addresses, also inside 6to4 and Teredo.
3. For a host with an `[[http]]` entry, the proxy terminates TLS, applies the rules of the entry and adds its credential. It speaks HTTP/1.1 and HTTP/2, so gRPC services, such as a Bazel remote cache, work through it.

Only the jail trusts the TLS authority, and it lasts for one session. [`doriath log`](/guides/inside-a-session/#session-history) shows each decision of the proxy.

## Credentials

doriath reads each [secret](/reference/configuration/#secrets) on the host when the session starts, and no secret enters the jail. The source is a command such as `rbw` or `bw`, the keyring of your desktop, or an OAuth login.

An `[[http]]` entry names the secret, its scheme and the programs that get it. With the [`github` module](/reference/modules/#github), only requests from `gh` and `git` carry your token. The agent can push through these programs, but it cannot read the token.

An SSH agent outside the jail signs commits with a key for the agent only, and refuses SSH logins. [Install](/install/#create-credentials-for-the-profile) shows how to create the key.

## Approvals

A request waits for your answer in these cases:

- An `[[http]]` rule holds it, for example for a merge, a release or a push.
- The profile does not name the host.
- The agent asks with `doriath request`, for example to write a path or to forward a port.
- An agent with an [adapter](/agents/#adapters), such as Claude Code, shows a permission prompt.

doriath holds the request while you decide, so an allow lets the first try through. No allow lasts longer than the session. Answers come only from your desktop, your terminal or the approvals page, which the jail cannot reach. See [answering requests](/guides/approvals/).

## Repositories

With the [`vcs-readwrite` module](/reference/modules/#vcs-readwrite), the agent edits your checkout, commits, makes branches and adds worktrees. Files that your machine runs on its own stay read-only. With `vcs-readonly`, the whole checkout stays read-only, and the agent works in worktrees. Either way the git and jj store is writable. The files that decide what git and jj run stay read-only: config, hooks, `info`, `commondir` and the jj store pointers.

When a session starts, doriath records your branches and bookmarks, and copies the loose objects. When it ends, doriath keeps the old position of each branch that the agent moved, removes objects that git cannot verify, and repairs the worktrees that the agent added. `doriath restore SESSION` puts moved branches back. [Repositories](/reference/configuration/#repositories) has the details.

## Containers and MCP servers

The `podman` module starts podman in its own user namespace. A broker checks each API call against the images and mounts of the profile. See [containers](/reference/configuration/#containers).

MCP servers come from the [`[[mcp]]`](/reference/configuration/#mcp-servers) list of the profile. For a remote server, doriath holds or refuses tools by name.

To run a command in the jail or reach one of its ports, read [looking inside a session](/guides/inside-a-session/).
