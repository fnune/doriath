`doriath run --profile NAME -- COMMAND` resolves the profile, starts a proxy and an approval queue on the host, and starts the command in a jail. The jail lasts as long as the command. When it ends, doriath repairs what the agent may have changed in your repositories and prints a summary of what it allowed, held and refused.

<Architecture />

## The jail

The jail is a set of Linux namespaces that bubblewrap creates, bundled in the `doriath` binary. The agent runs as your user, with its own mount, process and network namespaces.

| Part    | What the agent gets                                                                                                                                                                                                        |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Files   | The system is read-only, and the home directory, `/run`, `/tmp` and `/var` start empty. The repository you start in is read-only, with its git and jj store writable. Other paths appear only when the profile names them. |
| Kernel  | seccomp refuses namespaces, mounts, `ptrace`, `bpf`, `io_uring` and terminal injection. Landlock limits writes to the home directory, `/tmp` and the writable mounts.                                                      |
| Network | Only loopback. A small init in the jail forwards the proxy's port, so every connection the agent makes goes through doriath.                                                                                               |
| Limits  | A systemd user scope per session, with task and memory limits, and a CPU quota when the profile sets one.                                                                                                                  |

The environment starts empty too. The profile lists the host variables the jail may see, and the `base` module passes the usual ones, such as `PATH`, `TERM` and the locale.

## The proxy

The proxy runs on the host, outside the jail. For each connection it decides:

1. Is the host allowed? The profile's `[egress] allow` list and its modules name the hosts. A host the profile does not name becomes a request for you.
2. Is the address public? doriath refuses private, link-local, shared and metadata addresses, including IPv4 hidden inside 6to4 and Teredo, whatever name resolves to them.
3. Does the host have an `[[http]]` entry? Then the proxy terminates TLS with a certificate from a per-session authority that only the jail trusts, applies the entry's rules to each request, and adds the credential.

Every decision goes to the audit log, which `doriath log` reads.

## Credentials

A profile says where each secret comes from: a file, a command such as `rbw` or `secret-tool`, or an OAuth login doriath keeps on the host. doriath reads each one once per session and never puts it in the jail.

An `[[http]]` host names the secret, the scheme, and the programs that get it. With the `github` module, `gh` and `git` reach GitHub with your token while any other program reaches the same hosts without it. The agent can push and open pull requests, and it cannot read the token or send it elsewhere.

Commit signing works the same way: an SSH agent outside the jail holds an agent-only key, signs commits with it, and refuses SSH logins.

## Approvals

Some requests wait for you:

- a request an `[[http]]` rule holds, such as a merge, a release or a push
- a host the profile does not name
- a path the agent asks to write with `doriath request write`
- a Claude Code permission prompt, when the command is `claude`

doriath shows each one as a desktop notification and in `doriath approvals`, and holds the request while you decide, so an allow lets the first try through. After the wait the agent gets an error that says what to run, and the request stays answerable: an allow still lets the agent's next try through. An allow lasts at most until the session ends, and each request shows the profile lines that would keep it. See [answering requests](/guides/approvals/).

The agent cannot answer its own requests: decisions come only from your desktop session, your terminal or the approvals page, none of which the jail reaches.

## Repositories

With the `vcs` module, the agent commits, branches and adds worktrees while your checkout stays read-only. Each repository's store is writable: git's objects, refs, logs and worktrees, and jj's operation log. Everything that decides what git or jj runs stays read-only: config, hooks, `info`, `commondir` and jj's store pointers.

doriath records your branches and bookmarks when a session starts and keeps a copy of the loose objects. At the end it keeps the start value of each branch the agent moved, removes objects git cannot verify, and repairs each worktree the agent added so that it points back at your repository. `doriath restore SESSION` puts moved branches back.

## Extras

- A podman service in its own user namespace, behind a broker that checks each API call: containers may use the images the profile allows and bind only what it mounts.
- MCP servers from the profile's `[[mcp]]` list, with remote tools held or refused by name.
- `doriath exec` and `doriath forward` to run a command in the jail or reach one of its ports. See [looking inside a session](/guides/inside-a-session/).
