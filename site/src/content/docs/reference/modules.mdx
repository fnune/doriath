A module holds the mounts, caches, hosts, environment and request rules of one tool or service. A profile lists modules in `modules`, as [configuration](/reference/configuration/#profiles-and-modules) describes. Each section on this page shows the file that doriath ships.

- `doriath modules list` shows each module and where it comes from.
- `doriath modules show NAME` prints a module, and `--path` prints its path.
- `doriath profiles show NAME` names the module behind each mount, host and rule of a profile.

To change a built-in module, save a copy in `~/.config/doriath/modules/` with a new name, such as `my-github`, and list that name in its place. A copy with the name of a built-in module is an error, so that no module changes what a profile loads without notice.

## Modules in every profile

doriath loads these modules into every profile, before the profile's own modules. A profile cannot leave them out, and a later layer cannot remove their entries. They only refuse, warn on or hold paths, as [path lists](/reference/configuration/#path-lists) describes, so a new version of them does not ask you to allow a profile again. `doriath profiles show` does not list them.

### private-paths

`private-paths` refuses requests for the paths that hold your keys and logins, the config of git and jj, and the nix and home-manager profiles. doriath also refuses its own configuration, state and cache, which move with the XDG variables.

<ModuleSource name="private-paths" />

### login-autorun

`login-autorun` warns on requests for paths that your machine runs on its own: the folders in `PATH` such as `~/.local/bin`, systemd user units, autostart entries, session variables, and the startup files of your shells. Code that the agent writes there runs outside the jail.

<ModuleSource name="login-autorun" />

### shared-tmp

`shared-tmp` warns on requests to read or write `/tmp`. The host's `/tmp` holds the sockets of your X11 display and of agents such as ssh-agent, and the jail has its own `/tmp`.

<ModuleSource name="shared-tmp" />

### git-hook-managers

`git-hook-managers` keeps the config of lefthook, husky and pre-commit read-only in the session's repository when the jail can write it. These tools run their config as git hooks on your machine, such as at your next commit. doriath puts nothing at a name that is missing. If the agent creates one, such as a `lefthook-local.yml`, doriath moves it out of the repository at once and tells you where it went, as [path lists](/reference/configuration/#path-lists) describes.

<ModuleSource name="git-hook-managers" />

### direnv-files

`direnv-files` keeps `.envrc`, `.env` and the files that direnv loads through them read-only in the session's repository. doriath moves out a file that the agent creates at a missing name. Nix files that `use nix` reads in place of a missing `shell.nix`, such as `default.nix`, stay writable, because agents edit them in normal work.

<ModuleSource name="direnv-files" />

### editor-autorun

`editor-autorun` keeps the editor files that run when you open the project read-only in the session's repository, such as `.vscode`, `.nvim.lua` and `.exrc`. doriath moves out a file that the agent creates at a missing name. A missing `.vscode` gets an empty folder instead, which VS Code reads as no settings and can still write into. The module also warns on requests for the config of Neovim, Vim and Emacs in your home.

<ModuleSource name="editor-autorun" />

## vcs-readwrite

The agent edits and commits in the repository that you start in, and adds git worktrees or jj workspaces. The files that decide what git or jj runs stay read-only, as [repositories](/reference/configuration/#repositories) lists. So do the files of mise and of agents, such as `mise.toml` and `.claude/settings.json`, and the files that the [modules in every profile](#modules-in-every-profile) hold, such as `.envrc` and `.vscode`. The agent changes one of them with [`doriath request edit`](/reference/configuration/#edits), which shows you the new content first.

<ModuleSource name="vcs-readwrite" />

## vcs-readonly

`vcs-readwrite` with a read-only checkout. The agent commits, branches and adds worktrees, and cannot change your files. Use it for a session that reviews or answers questions. If a profile lists both modules, the checkout stays read-only.

<ModuleSource name="vcs-readonly" />

## maven

Maven Central, and a cache for the local repository. Java ignores `HTTPS_PROXY`, so doriath gives every JVM the proxy in `JAVA_TOOL_OPTIONS`. Maven uses it only with the flag that this module sets in `MAVEN_OPTS`.

<ModuleSource name="maven" />

## bazel

The Bazel client removes `JAVA_TOOL_OPTIONS` before it starts its server, so the server JVM would use neither the proxy nor the trust store. This module gives the server both. doriath writes the proxy and trust store settings as `startup --host_jvm_args` lines to `/etc/bazel.bazelrc` in the jail. Bazel reads that file in addition to the rc file of the workspace and your own `~/.bazelrc`. If your machine has an `/etc/bazel.bazelrc`, the jail keeps its lines and adds these after them.

The module allows no hosts. Add the hosts of your registry, remote cache and remote executors to `[egress]`. Older doriath versions wrote `~/.bazelrc` into every profile. A profile that relied on that file now needs `bazel` in `modules`.

<ModuleSource name="bazel" />

## nix

Caches and hosts for the Nix tools in the jail. For the daemon, add `nix-daemon`.

<ModuleSource name="nix" />

## nix-daemon

The nix daemon of your system, for `nix-shell -p`, `nix build` and `nix develop`. The builds run outside the jail, and reach the network without the allowlist. To keep more in the jail, enter a dev shell before `doriath run`.

<ModuleSource name="nix-daemon" />

## podman

A podman service for the session, behind a broker that checks each API call. Containers share the network of the session, so they reach the internet only through the proxy. See [containers](/reference/configuration/#containers).

<ModuleSource name="podman" />

## clipboard

Images from your clipboard, such as screenshots, after you [allow each read](/guides/approvals/#clipboard-images). The jail gets a Wayland display that offers only those images, so `wl-paste` and the Wayland protocol work as outside the jail. Text never reaches the jail through this display, and the agent cannot set your clipboard through it. The agent can still set the clipboard with an escape sequence in its terminal output, as the [threat model](/threat-model/#trust-that-returns-to-the-host) says. The module needs a Wayland session and wl-clipboard on your machine.

<ModuleSource name="clipboard" />
