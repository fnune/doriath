A module holds the mounts, caches, hosts, environment and request rules of one toolchain or service. A profile lists modules in `modules`, as [configuration](/reference/configuration/) describes. Each section on this page shows the file that doriath ships.

These commands show the modules on your machine:

- `doriath modules list` shows each module and where it comes from.
- `doriath modules show NAME` prints a module, and `--path` prints its path for an editor.
- `doriath profiles show NAME` names the module behind each mount, host and rule of a profile.

To change a built-in module, run `doriath modules edit NAME`. The command copies the module to `~/.config/doriath/modules/` and opens the copy. Your copy then replaces the built-in module in all profiles.

## base

Almost all profiles start with `base`. It mounts your nix profile and the config of jj, and passes `PATH` and the terminal and locale variables. It gives no network access.

<ModuleSource name="base" />

## vcs

With `vcs`, the agent can commit, branch and add git worktrees or jj workspaces in a read-only repository. The store becomes writable. The checkout, and all files that decide what git or jj runs, stay read-only. [Repositories](/reference/configuration/#repositories) has the full list.

<ModuleSource name="vcs" />

## docs

With `docs`, the agent can read documentation sites without an approval. No host in it accepts writes without a login, thus the agent cannot send data to these hosts.

<ModuleSource name="docs" />

## github

`github` adds your token to requests from `gh` and `git`, and the agent never sees the token. Give its source under `[secrets.github]` in the profile. [GitHub](/forges/github/) tells which requests go through, wait or are refused.

<ModuleSource name="github" />

## gitlab

`gitlab` adds your token to requests from `git` and `glab` on `gitlab.com`, and reads the encoded project paths of the GitLab API. [GitLab](/forges/gitlab/) tells which requests go through, wait or are refused.

<ModuleSource name="gitlab" />

## forgejo

`forgejo` covers Codeberg, and Forgejo or Gitea on a host of your own. It adds your token to requests from `git`, `tea`, `fj` and `berg`. See [Forgejo, Gitea and Codeberg](/forges/forgejo/).

<ModuleSource name="forgejo" />

## bitbucket

`bitbucket` adds your token to requests from `git` on `bitbucket.org` and from `curl` on `api.bitbucket.org`. See [Bitbucket](/forges/bitbucket/).

<ModuleSource name="bitbucket" />

## claude

For Claude Code, `claude` gives the profile its own `~/.claude` and its own login. Your `CLAUDE.md`, settings, skills and plugins are mounted read-only. Connectors are off, and doriath refuses all requests with an `x-api-key` header. See [Claude Code](/agents/claude-code/).

<ModuleSource name="claude" />

## go

With `go`, Go builds can reach the module proxy and the checksum database. The build, module and golangci-lint caches stay in the profile.

<ModuleSource name="go" />

## node

`node` allows the npm and Yarn registries and the Node.js downloads. It adds caches for npm, pnpm and node-gyp.

<ModuleSource name="node" />

## playwright

With `playwright`, Playwright downloads its browsers into a cache of the profile.

<ModuleSource name="playwright" />

## pre-commit

With `pre-commit`, pre-commit builds hook environments in a cache of the profile, from PyPI and the hook repositories.

<ModuleSource name="pre-commit" />

## nix

`nix` gives caches and hosts to the Nix tools in the jail. To reach the daemon, add the `nix-daemon` module.

<ModuleSource name="nix" />

## nix-daemon

`nix-daemon` connects the jail to the nix daemon of your system, for `nix-shell -p`, `nix build` and `nix develop`. The builds then run outside the jail, and reach the network without the allowlist. To keep more inside the jail, enter a dev shell before `doriath run`.

<ModuleSource name="nix-daemon" />

## podman

`podman` starts a podman service for the session in its own user namespace, behind a broker that checks each API call. Containers share the network of the session. Thus they reach the internet only through the proxy, and the agent reaches their ports on localhost. [Containers](/reference/configuration/#containers) describes images and binds.

<ModuleSource name="podman" />
