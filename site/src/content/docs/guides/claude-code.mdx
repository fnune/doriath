---
title: Claude Code
description: What doriath does for Claude Code, and what you set up once.
---

Your Claude configuration needs no change. When the command is `claude`, doriath:

- gives the profile its own `~/.claude`, through the `claude` module. Your `CLAUDE.md`, settings, skills and plugins are read-only there, and the login is the profile's own: run `/login` in a session. A new profile starts with your onboarding already done.
- starts Claude with generated settings: claude.ai connectors off, the profile's `ask` and `deny` rules, and the repository's `.claude/settings.json` frozen as it was at the start, so the agent cannot loosen its own permissions.
- tells the agent at session start what the jail allows, what `doriath:` errors mean, and how to ask for a host or a writable path.
- sends Claude's permission prompts to the [approval queue](/guides/approvals/). When you do not answer in time, Claude shows its own prompt.
- points Claude at the profile's MCP servers, from its `[[mcp]]` list. Your own MCP servers stay out of the jail.
- copies the project's transcripts back to your `~/.claude` when the session ends, so you can resume a session outside the jail.

Settings for the adapter live under `[claude]` in the profile:

```toml
[claude]
disable_connectors = true
statusline = true
ask = ["mcp__claude-in-chrome__javascript_tool"]
deny = []
# How long a permission prompt waits for you before Claude shows its own.
approval_timeout = "60s"
```

## Sharing your login

The profile's login is separate from yours, so the agent cannot use or swap your account. To share your login instead, mount your credentials file writable:

```toml
[[mounts]]
path = "~/.claude/.credentials.json"
mode = "write"
```

This lets the agent read the token, so it suits a profile you trust as much as yourself.

## Other agents

An agent without an adapter works in a jail too. Tell it one thing: "When something is blocked, run `doriath status`." Its errors from the proxy say what was blocked and what to run.
