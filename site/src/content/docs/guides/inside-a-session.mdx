---
title: Looking inside a session
description: Run commands in a jail, reach its ports, and read what it did.
---

The agent can start a server in the jail, for example a development server on port 3000. Only programs in the jail can connect to it. To use it from the host, run `doriath exec` or `doriath forward` in another terminal. The agent can also ask you to forward the port.

If more than one session runs, add `--session ID` to these commands. `doriath status` lists the sessions and their IDs, with the description that each agent gave its task through [`doriath describe`](/reference/commands/#doriath-describe).

## Run a command in the jail

```sh
doriath exec -- curl -sS http://localhost:3000
doriath exec
```

`doriath exec` runs a command as one more process of the jail, with the same files, network and limits as the agent. Without a command, it starts a shell.

## Reach a port of the jail

```sh
doriath forward 3000
```

This connects port 3000 on the host to port 3000 in the jail. All local users of the machine can connect to this port.

The agent asks for the same forward with `doriath request forward 3000`. When it opens a link such as `http://localhost:3000/`, doriath asks you to forward port 3000, and then opens the link. These forwards last until the session ends. See [ports](/guides/approvals/#ports). For a port that you reach in each session, put a [`[[forward]]`](/reference/configuration/#forwards) in the profile instead.

The agent reaches a port of your machine with `doriath request connect 3309`, for example a database tunnel that you opened on your machine. When a connection to `127.0.0.1` in the jail is refused, the agent can ask for the port. See [ports](/guides/approvals/#ports).

doriath connects to `127.0.0.1` in the jail, so the server must listen on that address. A server that listens only on `::1` does not get the connection.

To debug a browser in the jail, start it with `--remote-debugging-port=9222`. Then forward port 9222 and open `chrome://inspect` on the host.

## Session history

```sh
doriath status
doriath log --since 1h
doriath log --denied --follow
```

`doriath status` shows what a session allows and what it blocked. For each blocked request, it shows the profile lines that allow it.

doriath writes each session, egress decision and approval to the audit log, `~/.local/state/doriath/audit.jsonl`. Each record has its session and profile. `doriath log` reads this file, and `contrib/lnav` has a format for [lnav](https://lnav.org).

When a session ends, doriath prints what it blocked, the hosts that the session learned as profile lines, and the branches that moved. `doriath restore SESSION BRANCH` puts a branch back. See [Repositories](/reference/configuration/#repositories).

## Agent managers

An agent manager, such as [herdr](https://herdr.dev) or [sidecar](https://github.com/marcus/sidecar), shows the agents that run in its panes. It finds an agent from the name of its process. In a session, it sees `doriath` and `bwrap` in place of the agent. To name the agent to these two managers, set [`env` in `[terminal]`](/reference/configuration/#configtoml-keys) in `config.toml`:

```toml title="~/.config/doriath/config.toml"
[terminal]
env = { HERDR_AGENT = "{command}", SIDECAR_AGENT = "{command}" }
```

Other managers, such as claude-squad, agent-deck and ccmanager, start the agent themselves. Set the agent command in the manager to `doriath run --profile NAME -- claude`. A manager that gets the status of the agent from hooks through a socket does not get it, because the jail cannot reach the socket.
