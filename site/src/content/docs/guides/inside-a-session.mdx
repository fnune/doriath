---
title: Looking inside a session
description: Run commands in a jail, reach its ports, and read what it did.
---

The agent can start a server in the jail, for example a development server on port 3000. Only programs in the jail can connect to that server. To use it from the host, open another terminal and use `doriath exec` or `doriath forward`.

## Run a command in the jail

```sh
doriath exec -- curl -sS http://localhost:3000
doriath exec
```

`doriath exec` runs a command as one more process of the jail. Without a command, it starts a shell. The process gets the same files, network and limits as the agent.

## Reach a port of the jail

```sh
doriath forward 3000
```

`doriath forward 3000` connects port 3000 on the host to port 3000 in the jail. Then `localhost:3000` on the host goes to the server in the jail. All local users of the machine can connect to this port.

To debug a browser in the jail, start the browser with `--remote-debugging-port=9222`. Then forward port 9222 and open `chrome://inspect` on the host.

If more than one session runs, add `--session ID`. `doriath sessions` shows the IDs.

## Session history

```sh
doriath status
doriath log --since 1h
doriath log --denied --follow
```

`doriath status` shows what a session allows and what it blocked. For each blocked request, it also shows the profile lines that allow it.

doriath writes each session, each egress decision and each approval to the audit log, `~/.local/state/doriath/audit.jsonl`. Each record has its session and its profile. `doriath log` reads this file. The repository also has a format for [lnav](https://lnav.org) in `contrib/lnav`.

When a session ends, doriath prints one summary line. After it, doriath prints the hosts that the session learned, as profile lines. If the agent moved branches, `doriath restore SESSION` puts them back. [Repositories](/reference/configuration/#repositories) tells more about this.
