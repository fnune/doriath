A request waits for your answer when the agent reaches a host that the profile does not name, or [asks to write a path](#paths). An [`[[http]]` rule](/reference/configuration/#profile-keys) and the permission prompts of an agent with an [adapter](/agents/#adapters) also make requests. All requests go into one queue, and you can answer from each place on this page.

## Reading a request

The approvals page shows a request as below. Desktop notifications and the terminal show the same parts.

<RequestExample
  profile="infra"
  hue="p1"
  session="p71a"
  cwd="~/Development/infra"
  kind="tool"
  summary="Run a command"
  timer="39s"
  fill="65%"
  status="The agent is waiting for your answer, 39s left."
  note="Apply staging"
  details="deploy --env staging --yes"
  scope="tool claude Bash deploy"
/>

doriath writes the summary and the scope. The text on the curled rule with the agent's name comes from the agent, and so do the details of a tool request.

A request names what it does in a few words, such as Push or Request reviews, and lists the facts below it: what it acts on first, then the values that it changes. For an HTTP request, the action comes from the `summary` of its [rule](/reference/configuration/#profile-keys). Without one, it comes from the GraphQL field or the MCP tool, or it is the method and the path. The facts come from the rule's `subject`, the refs of a push, and the GraphQL variables, MCP arguments or JSON fields of the body. The raw request is folded below them.

When a rule gives a `link`, the request has a button with its label, such as Open PR. The button opens the page in your browser and does not answer the request.

A request for a host also shows what doriath knows about it:

- What the host is, from a note in the profile or its modules, under `[egress] notes`.
- The program that tried to reach it, and the command lines of that program and of each program that started it, such as `npm install` under the agent.
- How you answered requests for the same host in the last day, and in which profiles.
- The agent's reason, when it asked first with `doriath request host HOST --reason TEXT`.

When the timer ends, the agent gets an error and the request is parked. If you allow a parked request before the session ends, the next try of the agent goes through.

| Kind                        | The agent waits                                      | Set by                                                                    |
| --------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------- |
| `host`, `path`              | 2 minutes with desktop notifications, 0 without them | `host_wait` in [`config.toml`](/reference/configuration/#configtoml-keys) |
| `http`, podman image pushes | 10 minutes                                           | fixed                                                                     |
| `tool`                      | 60 seconds, then the agent shows its own prompt      | `tool_wait` in [`config.toml`](/reference/configuration/#configtoml-keys) |

While an `http` request or a connection to a host the profile does not name waits for more than 5 seconds, doriath writes one line to the standard error of the program that sent it. The line names the request and the ID, tells the agent not to retry, and gives the `doriath approvals allow` command. The agent then sees why the command is slow. doriath writes nothing when the program has no standard error, such as when it closed it or redirected it to a socket.

## Answers

- Allow once lets this request through. The next identical request asks again.
- Allow for this session lets identical requests through until the session ends. The line "An answer for the session covers" on the request shows what is identical.
- Deny for this session refuses identical requests until the session ends, and doriath does not ask you again. Requests for hosts, paths, reads, forwards and connects offer it.
- Deny refuses the request, and the agent gets an error. The next identical request asks again.

Hosts and writable paths have no "once", because the first allow opens them for the session. To keep an answer after the session, add the profile lines from the request to the [profile](/reference/configuration/). A request for a host shows the lines for an allow and the lines for a deny. doriath does not edit profiles, because a profile can come from Nix.

A request with a warning from doriath offers only Allow once and Deny, also for a path. doriath adds the warning to a request for a path that your machine runs or reads on its own, as [path lists](/reference/configuration/#path-lists) describes. The warning shows above the agent's text, and in red.

## Desktop notifications

On a machine with a desktop session, each request shows as a notification, through `[desktop] notifications = true` in `config.toml`. The title is the action. The body starts with the facts, then shows the agent's note or the command line in quotes, and ends with the session's description or its name. The lines to keep a request in the profile, and the scope, show only on the [approvals page](#the-approvals-page). The notification has the same answers as buttons as the page, and the link button when the request has one. While the page runs, a click on the notification itself opens the page at that request. Without a desktop session, doriath turns notifications off and tells you, as [remote hosts](#remote-hosts) describes.

## The approvals page

```sh
doriath web open
```

The page shows the requests of all running sessions and the answers of the last day. When nothing waits, it shows the checks of `doriath doctor`, and what the sessions of the last day blocked, with the profile lines to allow it. The page listens on `127.0.0.1:7341` and loads nothing from the network.

`doriath web open` opens the page with a link that works one time, for a minute. Then the browser keeps a cookie for 30 days. Other users and other sites cannot get a link, so they cannot read or answer requests.

Each open shows the page in a new tab, and the page then closes its older tabs. The browser lets a page close only a tab that has not gone to another page, so such a tab stays open.

The [home-manager](/guides/home-manager/#the-module) module runs the page as a systemd user service. To turn the service off, set `programs.doriath.desktop.web.enable = false`. Without the service, start the page with `doriath web`.

## The tray icon

While the page runs, its icon shows in the status area of your desktop. A dot marks the icon while requests wait for an answer. A click opens the page. The icon shows on desktops that support the StatusNotifierItem protocol, such as KDE Plasma, waybar, Xfce and LXQt. GNOME needs the AppIndicator extension. On KDE Plasma, the icon takes the colors of your panel and the accent color of your theme. Other desktops show it in doriath's colors.

To turn the icon off, set `[desktop] tray = false` in `config.toml`, or `programs.doriath.desktop.tray = false` in home-manager.

## The terminal

```sh
doriath approvals
doriath approvals allow ID --for session
doriath approvals deny ID --reason "use the staging stack"
```

`allow --for` and `deny --for` take `once`, `session` or a duration such as `30m`. [Commands](/reference/commands/) lists the flags.

## Remote hosts

On a server, notifications are off, so the agent does not wait for hosts and paths. To give it time, set a wait in the `config.toml` of the server:

```toml title="~/.config/doriath/config.toml"
[approvals]
host_wait = "2m"
```

Then run the approvals page on the server, and open it through an SSH tunnel from your own machine. No port opens to the network:

```sh
ssh -L 7341:127.0.0.1:7341 server
doriath web open --print
```

Open the printed link in your local browser within a minute. If you use another local port, such as `-L 8000:127.0.0.1:7341`, put `8000` in the link. Without a tunnel, answer with `doriath approvals` on the server.

<Aside type="note">
  The page answers only to loopback names in the Host header. If a site resolves
  its own name to 127.0.0.1, the page does not answer it in your browser.
</Aside>

## Paths

The agent asks for a path from inside the jail:

- `doriath request write PATH --reason TEXT` makes a path writable.
- `doriath request read PATH --reason TEXT` shows a folder that the jail does not show, read-only.
- `doriath request edit PATH --reason TEXT` changes one read-only file, such as `.git/config`, with the new content as input. You see what changes, and doriath writes it once.

An allow lasts until the session ends. A folder that the jail does not show must exist. A write request can cover paths that are already writable, such as a folder of the project that you allowed before. In a folder that the jail shows, the read-only and hidden paths inside keep their modes. doriath refuses a folder that the jail does not show when the profile mounts a read-only or hidden path inside it. doriath refuses some paths before it asks you, such as `.git`, `.ssh`, the paths that the profile hides and its own configuration, as [approvals](/reference/configuration/#approvals) lists. [Edits](/reference/configuration/#edits) lists the changes that need no answer.

To commit in another repository, the agent runs [`doriath request module MODULE PATH --reason TEXT`](/reference/commands/#doriath-request-module), such as with `vcs-readwrite`. The module applies there as in a session that starts there. A write request covers files only: git and jj cannot write the store of another repository with it.

doriath tells the agent to plan its changes first, its commits too, and ask once: for a module where it will commit, and otherwise for the narrowest path that covers them all.

## Secrets

When a secret is unavailable, such as after a login expires, the page shows a card for it. The card names the error and what fails without the secret. It holds the command that gives the session a value, [`doriath secrets provide`](/reference/commands/#doriath-secrets-provide), or `doriath profiles login` for an OAuth login.

- Try again reads the secret's source at once, such as after you sign in again.
- Dismiss stops the cards for that secret until the session ends. Requests that need it still fail.

The agent gets the id of the card in its error, and waits for it with `doriath request wait ID`.

## Links

When the agent opens a link that no rule allows, the page asks you: "Open a link to HOST in your browser?". It shows the whole link, and a warning when the link carries a long query, because your browser sends all of it to the site. Allow once opens this link. Allow for the session opens each later link that meets the same `[[open]]` rule, such as each link to `/settings/**` on the forge. For a link that no rule names, it opens each link to that host. A sign-in that redirects back to a port in the jail gets that port forwarded, as [links](/reference/configuration/#links) describes. A link to `localhost` goes to a server in the jail, so doriath asks you to [forward its port](#ports) first.

## Ports

When the agent runs `doriath request forward PORT`, the page asks you: "Forward port PORT on your machine into the jail?". A link to `localhost` asks for its port in the same way, and doriath opens the link after you allow it.

An allow makes doriath listen on the loopback address of your machine, and connect each connection to the port in the jail. Each program and each local user of your machine can then connect to the port. The forward lasts until the session ends. `doriath status` in the jail lists the forwards.

When the agent runs `doriath request connect HOST_PORT[:JAIL_PORT]`, the page asks you: "Let the jail connect to port HOST_PORT on your machine?". The card shows the host port, the jail port and the agent's reason. This is the reverse direction: a program in the jail can then connect to `127.0.0.1:JAIL_PORT`, and reach `127.0.0.1:HOST_PORT` on your machine. It reaches only that TCP port. The service there sees a client on your loopback address, so a service that trusts such clients, such as a database tunnel that is already signed in, also trusts the agent. Allow it only for a service that you accept the agent using. The grant lasts until the session ends, and `doriath status` in the jail lists it. For a port that every session of a profile needs, use [`egress.tcp_ports`](/reference/configuration/#profile-keys).

## Clipboard images

With the [clipboard module](/reference/modules/#clipboard), a paste of an image into the agent asks you first: "Let the agent read the image in your clipboard". Allow it once for each paste, or for the session. The agent can also ask when you did not paste, so a request that you did not expect means that the agent wants your clipboard on its own. Text is never offered.
