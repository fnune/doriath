A request waits for you when an [`[[http]]` rule](/reference/configuration/#profile-keys) holds it, when the agent reaches a host the profile does not name, when it [asks to write a path](#writable-paths), or when [Claude Code](/guides/claude-code/) raises a permission prompt. All of them land in one queue, and any of the places below can answer.

## Reading a request

This is a request on the approvals page, doriath's web interface, which `doriath approvals web --open` opens in your browser. Desktop notifications and the terminal show the same parts.

<RequestExample
  profile="infra"
  hue="p1"
  session="p71a"
  cwd="~/Development/infra"
  kind="tool"
  summary="Run a command"
  timer="39s"
  fill="65%"
  status="The agent is waiting for your answer, 39s left."
  note="Apply staging"
  details="acme up --stack staging --yes"
  scope="tool claude Bash acme up"
/>

doriath writes the summary and the scope. Anything the agent wrote, such as a command's description or its reason for a write, sits beside the curled rule with the agent's name on it, and for a tool request the details are the agent's as well.

The timer counts down the agent's wait. Once it runs out, the request is parked: the agent has an error and has moved on, and an allow still lets its next try through. Parked requests stay answerable until the session ends. How long the agent waits depends on the kind of request:

| Kind                                 | The agent waits                                            | Set by                                                                    |
| ------------------------------------ | ---------------------------------------------------------- | ------------------------------------------------------------------------- |
| `host`, `path`                       | 2 minutes with desktop notifications, no time without them | `host_wait` in [`config.toml`](/reference/configuration/#configtoml-keys) |
| `http`, and image pushes from podman | 10 minutes                                                 | fixed                                                                     |
| `tool`, from Claude Code             | 60 seconds, then Claude shows its own prompt               | `approval_timeout` under [`[claude]`](/guides/claude-code/)               |

## Answers

| Answer                 | Effect                                                                                                    |
| ---------------------- | --------------------------------------------------------------------------------------------------------- |
| Allow once             | Lets this request through. The next identical one asks again.                                             |
| Allow for this session | Lets identical requests through until the session ends. "An allow covers" shows what counts as identical. |
| Deny                   | Refuses the request with an error the agent sees.                                                         |

Hosts and writable paths have no "once", because a host stays reachable and a path stays written after the first allow. To keep an allow beyond the session, add the profile lines the request shows to the [profile](/reference/configuration/); doriath leaves profiles to you, since one may come from nix.

## Desktop notifications

On a machine with a desktop session, each request becomes a notification with the answers as buttons. They are on by default, through `[approvals] desktop = true` in `config.toml`. Where no desktop session runs, such as on a server over SSH, doriath turns them off when the session starts and says so; see [remote hosts](#remote-hosts) for what to use there.

## The approvals page

```sh
doriath approvals web --open
```

Requests from every running session appear on the page, next to the last day's answers from the audit log. It serves on `127.0.0.1:7341` and prints a link with a token, which the browser then keeps in a cookie for 30 days. Other users of the machine and other sites have no token, so they can neither read nor answer, and the page loads nothing from the network.

Running the command again while the page serves prints the link again, after the page proves it holds your token. With [home-manager](/guides/home-manager/#the-module), `programs.doriath.approvals.web.enable = true` keeps the page running as a systemd user service.

## The terminal

```sh
doriath approvals
doriath approvals allow ID --for session
doriath approvals deny ID --reason "use the staging stack"
doriath approvals watch
```

`allow --for` takes `once`, `session` or a duration such as `30m`. `watch` goes through new requests one at a time. [Commands](/reference/commands/) lists the flags.

## Remote hosts

On a server, doriath and its jails run there, and you answer from your own machine. No desktop session runs on the server, so notifications are off, and with them the default wait for hosts and paths drops to nothing: the agent gets an error at once and the request parks. Give the agent time to wait for you in the server's `config.toml`:

```toml title="~/.config/doriath/config.toml"
[approvals]
host_wait = "2m"
```

Then run the approvals page on the server, on its loopback address, and reach it through an SSH tunnel, so that no port opens to the network:

```sh
ssh -L 7341:127.0.0.1:7341 server
doriath approvals web
```

Open the printed link in a browser on your own machine. Another local port works too, such as `-L 8000:127.0.0.1:7341`, with `8000` in the link. To keep the page up between logins, run it as the home-manager service on the server, and print the link again with `doriath approvals web` when you need it. Without a tunnel, `doriath approvals watch` in a terminal on the server answers the same requests.

<Aside type="note">
  The page answers only to loopback names in the Host header. A site that
  resolves its own name to 127.0.0.1 gets no response from it in your browser.
</Aside>

## Writable paths

From inside the jail, `doriath request write PATH --reason TEXT` asks for a path to become writable, and `doriath request wait ID` blocks until you answer. Only paths the agent already sees qualify, and some are refused before you are asked, `.git`, `.ssh` and doriath's own configuration among them; [configuration](/reference/configuration/#approvals) has the full list.

`doriath grant write PATH` on the host makes a path writable in the running session directly. It can also attach a directory the jail does not see yet.
