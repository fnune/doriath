A request waits for your answer when the agent reaches a host that the profile does not name, or [asks to write a path](#writable-paths). An [`[[http]]` rule](/reference/configuration/#profile-keys) and the permission prompts of an agent with an [adapter](/agents/#adapters) also make requests. All requests go into one queue, and you can answer from any place on this page.

## Reading a request

The approvals page shows a request as below. Desktop notifications and the terminal show the same parts.

<RequestExample
  profile="infra"
  hue="p1"
  session="p71a"
  cwd="~/Development/infra"
  kind="tool"
  summary="Run a command"
  timer="39s"
  fill="65%"
  status="The agent is waiting for your answer, 39s left."
  note="Apply staging"
  details="acme up --stack staging --yes"
  scope="tool claude Bash acme up"
/>

doriath writes the summary and the scope. The text on the curled rule with the agent's name comes from the agent, and so do the details of a tool request.

A request for a host also shows what doriath knows about it:

- What the host is, from a note in the profile or its modules, under `[egress] notes`.
- The program that tried to reach it, and the command lines of that program and of each program that started it, such as `npm install` under the agent.
- How you answered requests for the same host in the last day, and in which profiles.
- The agent's reason, when it asked first with `doriath request host HOST --reason TEXT`.

When the timer ends, the agent gets an error and the request is parked. If you allow a parked request before the session ends, the next try of the agent goes through.

| Kind                        | The agent waits                                      | Set by                                                                    |
| --------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------- |
| `host`, `path`              | 2 minutes with desktop notifications, 0 without them | `host_wait` in [`config.toml`](/reference/configuration/#configtoml-keys) |
| `http`, podman image pushes | 10 minutes                                           | fixed                                                                     |
| `tool`                      | 60 seconds, then the agent shows its own prompt      | `tool_wait` in [`config.toml`](/reference/configuration/#configtoml-keys) |

## Answers

| Answer                 | Effect                                                                                             |
| ---------------------- | -------------------------------------------------------------------------------------------------- |
| Allow once             | Lets this request through. The next identical request asks again.                                  |
| Allow for this session | Lets identical requests through until the session ends. "An allow covers" shows what is identical. |
| Deny                   | Refuses the request. The agent gets an error.                                                      |

Hosts and writable paths have no "once", because the first allow opens them for the session. To keep an allow after the session, add the profile lines from the request to the [profile](/reference/configuration/). doriath does not edit profiles, because a profile can come from Nix.

A request with a warning from doriath offers only Allow once and Deny, also for a path. doriath adds the warning to a request for a path that your machine runs or reads on its own, as [path lists](/reference/configuration/#path-lists) describes. The warning shows above the agent's text, and in red.

## Desktop notifications

On a machine with a desktop session, each request shows as a notification, with the same answers as buttons as the [approvals page](#the-approvals-page). While the page runs, a click on the notification itself opens the page at that request. They are on by default, through `[approvals] desktop = true` in `config.toml`. Without a desktop session, doriath turns them off at session start and tells you. For that case, see [remote hosts](#remote-hosts).

## The approvals page

```sh
doriath web open
```

The page shows the requests of all running sessions and the answers of the last day. When nothing waits, it shows the checks of `doriath doctor`, and what the sessions of the last day blocked, with the profile lines to allow it. The page listens on `127.0.0.1:7341` and loads nothing from the network.

`doriath web open` opens the page with a link that works one time, for a minute. Then the browser keeps a cookie for 30 days. Other users and other sites cannot get a link, so they cannot read or answer requests.

The page runs as a systemd user service when you set `programs.doriath.approvals.web.enable = true` in [home-manager](/guides/home-manager/#the-module). Without the service, start the page with `doriath web`.

## The terminal

```sh
doriath approvals
doriath approvals allow ID --for session
doriath approvals deny ID --reason "use the staging stack"
```

`allow --for` takes `once`, `session` or a duration such as `30m`. [Commands](/reference/commands/) lists the flags.

## Remote hosts

On a server, notifications are off, so the agent does not wait for hosts and paths. To give it time, set a wait in the `config.toml` of the server:

```toml title="~/.config/doriath/config.toml"
[approvals]
host_wait = "2m"
```

Then run the approvals page on the server, and open it through an SSH tunnel from your own machine. No port opens to the network:

```sh
ssh -L 7341:127.0.0.1:7341 server
doriath web open --print
```

Open the printed link in your local browser within a minute. If you use another local port, such as `-L 8000:127.0.0.1:7341`, put `8000` in the link. Without a tunnel, answer with `doriath approvals` on the server.

<Aside type="note">
  The page answers only to loopback names in the Host header. If a site resolves
  its own name to 127.0.0.1, the page does not answer it in your browser.
</Aside>

## Paths

To ask for a writable path from inside the jail, run `doriath request write PATH --reason TEXT`. To ask to read a folder that the jail does not show, run `doriath request read PATH --reason TEXT`. Each request waits for you on the approvals page, and an allow lasts until the session ends. To wait for your answer, run `doriath request wait ID`.

- A folder that the jail does not show must exist. Otherwise doriath tells the agent to ask you to create it.
- A read shows the whole folder read-only. doriath refuses a folder that holds a path the profile hides.
- doriath refuses some paths before it asks you, such as `.git`, `.ssh` and its own configuration. [Configuration](/reference/configuration/#approvals) has the full list.

To commit in another repository, the agent runs [`doriath request module MODULE PATH --reason TEXT`](/reference/commands/#doriath-request-module), such as with `vcs-readwrite`. The module applies there as in a session that starts there. A write request covers files only: git and jj cannot write the store of another repository with it.

doriath tells the agent to plan its changes first, its commits too, and ask once. It asks for a module where it will commit, and otherwise for the narrowest file or directory that covers all changes. Each edit request below asks you again.

Where `request write` refuses, such as `.git/config`, the agent runs `doriath request edit PATH --reason TEXT` with the new content as input. The request shows what changes, and doriath writes it once. [Edits](/reference/configuration/#edits) lists the changes that need no answer.

## Secrets

When a secret is unavailable, such as an expired login, the page shows a card for it. The card names the error and what fails without the secret. It holds the command that gives the session a value, [`doriath secrets provide`](/reference/commands/#doriath-secrets-provide), with a button that copies it. For an OAuth login, it holds `doriath profiles login` instead.

- **Try again** reads the secret's source at once, such as after you log in again.
- **Dismiss** stops the cards for that secret until the session ends. Requests that need it still fail.

The agent gets the request's id in its error, and waits for the card with `doriath request wait ID`.

## Links

When the agent opens a link that no rule allows, the page asks you: "Open a link to HOST in your browser?". It shows the whole link, and a warning when the link carries a long query, because your browser sends all of it to the site. Allow once opens this link. Allow for the session opens each later link that meets the same `[[open]]` rule, such as each link to `/settings/**` on the forge. For a link that no rule names, it opens each link to that host. A sign-in that redirects back to a port in the jail gets that port forwarded, as [links](/reference/configuration/#links) describes.

## Clipboard images

With the [clipboard module](/reference/modules/#clipboard), pasting an image into the agent asks you first: "Let the agent read the image in your clipboard". Allow it once for each paste, or for the session. The agent can ask whenever it likes, not only when you paste, so an unexpected request means the agent wants your clipboard on its own. Text is never offered.
