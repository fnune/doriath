title: home-manager
description: Install doriath and write its profiles in a home-manager configuration, alongside TOML profiles kept elsewhere.
---

[home-manager](https://github.com/nix-community/home-manager) manages a user's programs and dotfiles from a Nix configuration, the way NixOS manages a system. doriath ships a home-manager module, so the binary, its direnv and shell integration, the approvals page service and your profiles can all live in that configuration and change when you switch to a new generation. Without Nix, skip this page: the [release binary](/install/) and TOML profiles in `~/.config/doriath/profiles/` do the same.

## The module

Add the flake as an input and import its module:

```nix title="flake.nix"
{
  inputs.doriath = {
    url = "github:fnune/doriath";
    inputs.nixpkgs.follows = "nixpkgs";
    inputs.home-manager.follows = "home-manager";
  };
}
```

```nix
{
  imports = [ inputs.doriath.homeManagerModules.default ];

  programs.doriath = {
    enable = true;
    approvals.web.enable = true;
  };
}
```

| Option                 | Default                  | What it does                                                                                |
| ---------------------- | ------------------------ | ------------------------------------------------------------------------------------------- |
| `enable`               | `false`                  | Installs doriath and writes `~/.config/doriath/config.toml`.                                |
| `direnv`               | `programs.direnv.enable` | Installs the [direnv](/guides/direnv/) library, for `use doriath PROFILE`.                  |
| `zsh.completion`       | `programs.zsh.enable`    | Loads the zsh completion.                                                                   |
| `approvals.desktop`    | `true`                   | Shows requests as desktop notifications.                                                    |
| `approvals.web.enable` | `false`                  | Runs the [approvals page](/guides/approvals/#the-approvals-page) as a systemd user service. |
| `approvals.web.listen` | `"127.0.0.1:7341"`       | The loopback address of the page.                                                           |
| `profiles.<name>`      | `{ }`                    | Profiles, with the same keys as their TOML.                                                 |
| `modules.<name>`       | `{ }`                    | Your own modules. A module with a built-in's name replaces it.                              |

## Profiles in Nix

A profile in Nix takes the same keys as its TOML file, as attributes, and adds `packages`: tools that land in front of the jail's `PATH` without being installed on the host.

```nix
programs.doriath.profiles.my-app = {
  description = "My app";
  modules = [ "base" "vcs" "go" "github" "claude" ];
  secrets.github.command = [ "rbw" "get" "github-my-app" ];
  packages = [ pkgs.xvfb-run ];
  mounts = [
    {
      path = "~/Development/.worktrees/my-app";
      mode = "write";
    }
  ];
};
```

home-manager writes each one to `~/.config/doriath/profiles/<name>.toml` as a link into the Nix store. `doriath profiles edit` refuses those and points you back to the Nix configuration.

## Profiles kept elsewhere

Some profiles fit better outside the Nix configuration: one a team keeps in a repository of its own, one you change more often than you switch generations, or one that names more of a project than you want in a configuration other people read. Keep those as TOML files in a folder of their own, and link the folder into the profiles folder once:

```sh
git clone git@github.com:acme/doriath-profiles.git ~/Development/doriath-profiles
ln -s ~/Development/doriath-profiles ~/.config/doriath/profiles/acme
```

doriath looks for profiles in `~/.config/doriath/profiles/` and in every folder inside it, following links and skipping names that start with a dot, such as `.git`. The file name is the profile name, so `acme/acme-service.toml` is `--profile acme-service`, and two files with one name are an error. The profiles home-manager writes sit next to the link and leave it alone, so both kinds work side by side.
